1. Nombres, Vinculación (Binding), Estructuras de Control y Alcance (Scoping)

1.1 Nombres, Palabras Reservadas e Identificadores

Según ECMA-334 (Cap. 6), los identificadores en C# son sensibles a mayúsculas y minúsculas (case-sensitive), admiten letras Unicode o guion bajo inicial, y distinguen entre palabras clave reservadas (class, struct, ref, in, out, switch) y palabras clave contextuales (record, init, var, required), permitiendo expandir el lenguaje sin romper compatibilidad con código previo. En el Mini-REPL, SpanLexer clasifica cada lexema sobre ReadOnlySpan<char> verificando primero operadores y palabras reservadas RPN (true, false, begin, end), luego literales numéricos y finalmente identificadores de usuario.

1.2 Tiempos de Vinculación (Binding Times) y Semántica L-value vs. R-value

C# es principalmente de vinculación estática (en compilación con Roslyn), articulando tres instantes de enlace: (a) tiempo de diseño (operadores nativos, System.Int64, System.Double y promoción numérica §10.2.3); (b) tiempo de compilación (resolución de nombres, chequeo de tipos, sobrecargas y flujo nulo); y (c) tiempo de ejecución (JIT/CLR) (despacho dinámico de interfaces IRpnOperation.Apply y resolución dinámica de variables del Mini-REPL en SymbolEnvironment).

En notación postfija estricta, al leer el primer token de x 10 = o x x 1 + = aún se desconoce si x se usará como valor (R-value) o como destino izquierdo de asignación (L-value). Siguiendo a Strachey, el tipo algebraico StackSlot modela ambos estados en la pila:

src/RpnRepl/Types/StackSlot.csL-value vs. R-value en pila
public abstract record StackSlot {
    private StackSlot() { }
    public sealed record ValueSlot(RpnValue Value) : StackSlot;
    public sealed record SymbolSlot(string Name, RpnValue? CapturedValue, int? ScopeDepth, SourceSpan Span) : StackSlot;
}

Si la variable existe al leerse, SymbolSlot captura su valor actual (CapturedValue) como R-value inmediato y preserva su Name como L-value potencial para =. Si no existía y ningún = la consume al finalizar la línea, FindDanglingUndefinedSymbol reporta RpnError.UndefinedVariable tras revertir transaccionalmente la pila.

1.3 Estructuras de Control y Contexto Aritmético checked

Junto a las estructuras imperativas tradicionales (ECMA-334 §13: if/switch, while/for/foreach), C# ofrece expresiones switch con pattern matching posicional, de tipo y relacional. En RpnEvaluator.cs y ArithmeticOperation se combinan bucles foreach, expresiones switch y bloques checked { ... }.

Detalle de Especificación: Contexto checked vs. unchecked (ECMA-334 §12.8.20)
Por defecto en C#, la aritmética entera es unchecked (desbordamiento silencioso en complemento a dos). En ArithmeticOperation.ApplyInt se usa un bloque checked { ... } para que operaciones como 9223372036854775807 1 + disparen OverflowException, capturada y convertida en RpnError.ArithmeticOverflow sin abortar el REPL.

1.4 Reglas de Alcance (Scoping) y Shadowing: C# frente al Mini-REPL

C# aplica alcance léxico estático por bloques ({ ... }, §7.6) y prohíbe el shadowing de variables locales en bloques anidados del mismo método (error CS0136), permitiendo solo sombrear campos de clase (desambiguados con this.). En cambio, para soportar bloques locales temporales begin ... end en el Mini-REPL, SymbolEnvironment utiliza una cadena enlazada de marcos ScopeFrame con búsqueda ascendente y escritura estricta en el marco más interno (_currentScope.BindLocal), generando shadowing local temporal sin sobrescribir las variables globales al ejecutar end.

2. Sistema de Tipos de Datos y Chequeo de Tipos

2.1 El Common Type System (CTS) y Emulación de ADTs Cerrados en C# 12

El sistema de tipos de C# (ECMA-334 §8) se fundamenta en el Common Type System (CTS) del CLR, dividiendo los tipos en tipos por valor (struct, enum, readonly record struct) y tipos por referencia (class, record class, interface), con genéricos reificados en ejecución. Para representar valores, tokens y errores del evaluador (Requisito #2), empleamos Tipos Algebraicos de Datos (ADTs) cerrados mediante abstract record con constructor private y variantes internas sealed record:

src/RpnRepl/Types/RpnValue.cs & Diagnostics/RpnError.csADTs cerrados en C# 12
public abstract record RpnValue {
    private RpnValue() { } // Impide herencia externa: suma cerrada de variantes
    public sealed record IntValue(long Value) : RpnValue { ... }
    public sealed record FloatValue(double Value) : RpnValue { ... }
    public sealed record BoolValue(bool Value) : RpnValue { ... }
}

2.2 Chequeo Estático, Flujo Nulo, Inferencia y Chequeo Dinámico del Evaluador

La verificación opera en dos planos complementarios: (1) Chequeo estático en C# (Roslyn) con <Nullable>enable</Nullable>, <TreatWarningsAsErrors>true</TreatWarningsAsErrors> y atributos [NotNullWhen(true/false)] en EvalResult<T>, además de inferencia local estática (var, new(...), [...]); y (2) Chequeo dinámico en el Mini-REPL (TypeChecker.cs) sobre las variantes de RpnValue: Int con Int produce Int (incluyendo división entera 7 2 / → 3), la mezcla con Float promueve a Float (§10.2.3), y toda combinación inválida con Bool (5 true +, 5 true ==) produce RpnError.TypeMismatch.

src/RpnRepl/Engine/TypeChecker.csPromoción numérica y rechazo de Bool
public static EvalResult<NumericOperands> PromoteNumericPair(string op, RpnValue left, RpnValue right, in SourceSpan span) =>
    (left, right) switch {
        (RpnValue.IntValue a, RpnValue.IntValue b)     => EvalResult<NumericOperands>.Ok(new NumericOperands.IntPair(a.Value, b.Value)),
        (RpnValue.FloatValue a, RpnValue.FloatValue b) => EvalResult<NumericOperands>.Ok(new NumericOperands.FloatPair(a.Value, b.Value)),
        (RpnValue.IntValue a, RpnValue.FloatValue b)   => EvalResult<NumericOperands>.Ok(new NumericOperands.FloatPair(a.Value, b.Value)),
        (RpnValue.FloatValue a, RpnValue.IntValue b)   => EvalResult<NumericOperands>.Ok(new NumericOperands.FloatPair(a.Value, b.Value)),
        _ => EvalResult<NumericOperands>.Fail(new RpnError.TypeMismatch(op, left.TypeName, right.TypeName, "(Int|Float, Int|Float)", span))
    };

2.3 Equivalencia Nominal, Igualdad Estructural y Comparativa de Lenguajes

La equivalencia de tipos en C# es nominal (dos class o record con campos idénticos son tipos distintos), pero record y readonly record struct generan automáticamente igualdad estructural por valor (Equals, ==, GetHashCode) y copias no destructivas con with.

3. Subrutinas, Mecanismos de Paso de Parámetros y Manejo de Memoria

3.1 Subrutinas y Paso de Parámetros en C# (ECMA-334 §15.6.2)

En RpnEvaluator, la pila (EvaluationStack) y la tabla de símbolos (SymbolEnvironment) se pasan explícitamente a cada subrutina para demostrar todos los mecanismos de paso de parámetros de C#:

3.2 Gestión de Memoria: Stack, Managed Heap, ref struct y Garbage Collector

El CLR divide la ejecución entre el Stack de hilo (liberación determinista O(1)) y el Managed Heap (GC generacional Gen 0/1/2). Para evitar asignaciones en el Heap al tokenizar, SpanTokenScanner se declara como ref struct sobre ReadOnlySpan<char>; el compilador prohíbe su boxing o almacenamiento en clases, garantizando que resida estrictamente en el Stack.

4. Abstracción de Datos y Conceptos de Programación Orientada a Objetos

4.1 Encapsulación, Modificadores de Acceso e Invariantes

Mediante modificadores de acceso (§7.5: public, private, protected, internal, init), EvaluationStack y ScopeFrame ocultan sus colecciones mutables internas (_slots, _bindings) como private readonly y exponen únicamente vistas de solo lectura (IReadOnlyList<StackSlot>, IReadOnlyDictionary<string, RpnValue>) o la interfaz segregada IScopeLookup.

4.2 Interfaces vs. Clases Abstractas: Polimorfismo Abierto y Composición

C# separa herencia simple de implementación múltiple de interfaces (§19). El motor combina polimorfismo abierto por interfaces y composición (IRpnOperation, IOperationRegistry, inyectado en el constructor primario de RpnEvaluator) con polimorfismo cerrado mediante abstract record (Token, RpnValue, RpnError) para dominios de variantes fijas.

5. Verificación Práctica y Sesión Demostrativa del Mini-REPL

El evaluador aplica el algoritmo clásico de pila LIFO para Notación Polaca Inversa (sin paréntesis y preservando el orden relativo de operandos: en operadores no conmutativos como - y /, TryPopTwoRValues extrae el tope como operando derecho y el inmediato inferior como izquierdo, evaluando 10 2 - → 8 y 15 7 1 1 + - / 3 * 2 1 1 + + - → 5).
